# Установка агентом

**Для ИИ-агентов.** Используйте CLI setup, чтобы установить Unity Open MCP в
один проект Unity. Выполните агентские шаги самостоятельно и остановитесь только
на блоке **ДЕЙСТВИЕ ПОЛЬЗОВАТЕЛЯ**.

Для людей этот путь экспериментальный. В качестве альтернативы доступны
[ручная установка](manual-setup.md) и [мастер](wizard-setup.md).

Если проект уже установлен и открыт в Unity, не запускайте первичную установку
повторно только ради смены версии. Используйте **Tools → Unity Open MCP Bridge
→ Status → Updates** или сначала вызовите `unity_open_mcp_upgrade` с
`dry_run: true`: оба пути согласованно обновляют пакеты, конфигурацию и
агентские документы после просмотра плана.

## Жёсткие правила

1. Загружайте эту инструкцию заново или читайте её из локального чекаута. Не
   устанавливайте по запомненным фрагментам.
2. Все версии определяет запущенный пакет `unity-open-mcp`. Не выдумывайте
   версию и не правьте привязки вручную до попытки запуска CLI.
3. CLI копирует байты `SKILL.md`, поставляемые в npm-пакете. Не переписывайте
   скил и не вызывайте `unity_open_mcp_generate_skill` во время установки.
4. Настройте один обнаруженный клиент. Не заполняйте каталоги всех клиентов.
5. Не добавляйте необязательные доменные пакеты без просьбы человека.

## 1) Определите проект и клиент

Найдите абсолютный корень проекта Unity — каталог с `Assets/`, `Packages/` и
`ProjectSettings/`. Уберите завершающий слеш.

Заодно определите, совпадает ли этот корень с папкой, на которой открыт
ИИ-клиент человека. Если проект Unity лежит в подпапке большего репозитория
(`<repo>/Client`) — это монорепозиторий, и в шаге 2 нужна команда для
конфигурации, пригодной к коммиту.

| Клиент | `--client` | Конфигурация в проекте |
|---|---|---|
| Cursor | `cursor` | `.cursor/mcp.json` |
| Claude Code / проектный Claude | `claude` | `.mcp.json` |
| OpenCode | `opencode` | `opencode.json` |
| Универсальные агенты | `agents` | `.mcp.json` |

Если клиент неясен, спросите человека один раз. Другие id скилов распознаются,
но команда откажется от них, поскольку не может безопасно записать MCP-конфиг;
для них используйте [каталог ручной настройки](client-configuration.md).

Проверьте Node.js 18+ командой `node --version`. Если Node отсутствует или
устарел, попросите установить Node LTS и перезапустить терминал/клиент.

## 2) Запустите setup

```bash
npx -y unity-open-mcp@latest setup \
  --project /absolute/path/to/UnityProject \
  --client cursor
```

Загруженный пакет привязывает все три компонента к **собственной версии**. Он:

- объединяет Git-привязки bridge и verify с `Packages/manifest.json`;
- объединяет сервер `unity-open-mcp` с проектным MCP-конфигом, сохраняя другие
  серверы и дополнительные переменные окружения;
- побайтно копирует встроенный основной скил в путь выбранного клиента;
- не запускает Unity, не подключается к bridge и не ставит доменные пакеты.

### Монорепозиторий: конфигурация для коммита

Когда проект Unity лежит в подпапке репозитория, назовите раскладку. Тогда
конфигурация и скил уходят в корень репозитория (там открыт клиент), привязки
Unity по-прежнему в проект Unity, а записанная запись не содержит машинного
пути — команда коммитит её один раз:

```bash
npx -y unity-open-mcp@latest setup \
  --project /absolute/path/to/repo/Client \
  --client cursor \
  --layout monorepo --unity-subpath Client
```

Для монорепозитория это основной путь: он лучше, чем просить каждого
разработчика править абсолютный путь. Подробности и матрица клиентов —
[Переносимая конфигурация MCP](portable-config.md).

Параметры: `--dry-run` ничего не записывает; `--skip-skill` не трогает скил;
`--json` выдаёт стабильный машинный отчёт; `--layout monorepo --unity-subpath
<rel>` пишет форму для коммита, `--portable` делает то же для однопроектного
репозитория, `--no-portable` возвращает абсолютный путь; `--workspace <abs>`
задаёт корень репозитория явно; `--wrapper` дополнительно пишет скрипт-обёртку;
`setup --help` работает без обязательных параметров. Код `0` — успех, `2` —
ошибка проекта/клиента, `1` — ошибка чтения, разбора JSON или записи.

## 3) Проверьте отчёт

Убедитесь, что отчёт показывает `VERSION`, две UPM-привязки с этой версией,
путь MCP-конфига и `unity-open-mcp@VERSION`, а также один путь скила и размер
в байтах (если не задан `--skip-skill`). Для монорепозитория или запуска с
`--portable` отчёт дополнительно показывает корень рабочей области, раскладку и
строку `Config: portable — safe to commit`. Если во фрагменте всё же остался
абсолютный путь, сообщите об этом вместо коммита.

## 4) ДЕЙСТВИЕ ПОЛЬЗОВАТЕЛЯ

Попросите человека:

1. Открыть тот же проект в Unity и дождаться окончания компиляции.
2. Перезапустить MCP / ИИ-клиент, чтобы он перечитал конфигурацию.
3. При желании открыть **Tools → Unity Open MCP Bridge** и проверить состояние.

После подтверждения вызовите `unity_open_mcp_capabilities` или
`unity_open_mcp_ping`, если инструменты видны.

## Ручной запасной путь

Для неподдерживаемого клиента используйте [настройку MCP-клиента](client-configuration.md),
[ручную установку](manual-setup.md) или [мастер](wizard-setup.md). Все привязки
должны иметь одну версию; не выдумывайте её и не переписывайте скил.

См. также [устранение неполадок](../../troubleshooting.md).
